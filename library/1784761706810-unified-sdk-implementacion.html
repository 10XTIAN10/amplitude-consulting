1. Instalación e Inicialización

Paso 1 — Instalar el paquete

npm install @amplitude/unified

Paso 2 — Inicializar en el entry point de la app

Este código va una sola vez, en el archivo raíz de tu aplicación (por ejemplo main.ts, App.tsx o index.ts), antes de cualquier track o identify.

import { initAll } from "@amplitude/unified";

initAll("TU_API_KEY", {
  serverZone: "US",          // o "EU" si tus datos están en Europa
  analytics: {
    defaultTracking: true,   // trackea page views y clicks automáticamente
  },
  sessionReplay: {
    sampleRate: 0.5,         // graba el 50% de las sesiones
  },
  engagement: {
    // Guides & Surveys activo por defecto
    // Para desactivarlo: skip: true
  },
});
Guides & Surveys está habilitado por defecto con solo incluir el bloque engagement. No necesitás ninguna configuración adicional para que funcione. Si quisieras desactivarlo, usarías engagement: { skip: true }.

2. ¿Para qué sirve identify()?

identify() es la función que le dice a Amplitude quién es el usuario y cuáles son sus atributos. Es independiente de los eventos: no registra una acción, sino que actualiza el perfil del usuario.

Flujo de identify()

Diferencia clave entre track() e identify()

track()identify()
¿Qué registra?Una acción que ocurrióAtributos del usuario
¿Cuándo se usa?Cuando el usuario hace algoCuando sabés algo nuevo del usuario
¿Disponible para Guides?No directamenteSí, en tiempo real
¿Persiste entre sesiones?No aplicaSí, en localStorage
Ejemplo"reserva_completada"tipo_viajero = "aventura"

Métodos disponibles en la clase Identify

import { identify, Identify } from "@amplitude/unified";

const id = new Identify();

id.set("plan", "premium");               // asigna o sobreescribe
id.setOnce("primer_destino", "Bariloche"); // solo si no existe aún
id.add("reservas_completadas", 1);       // incrementa un número
id.append("destinos_visitados", "Mendoza"); // agrega al final de un array
id.prepend("destinos_visitados", "Salta");  // agrega al inicio de un array
id.preInsert("tags", "vip");             // agrega al inicio solo si no existe
id.postInsert("tags", "activo");         // agrega al final solo si no existe
id.remove("destinos_visitados", "Salta"); // elimina un valor del array
id.unset("promo_code");                  // elimina la propiedad

identify(id);

3. Cómo y dónde cargar identify()

Hay dos momentos clave donde siempre debés llamar a identify():

Cuándo llamar a identify()

Regla de oro

Llamá a identify() al inicio de cada sesión con los datos frescos del usuario traídos desde tu API. Luego, llamalo de nuevo solo cuando una propiedad cambia durante la sesión (por ejemplo, al completar una reserva).

Las propiedades persisten en localStorage, por lo que si el usuario vuelve sin que nada haya cambiado, las propiedades de la sesión anterior siguen disponibles. Pero como los datos del backend pueden haber cambiado (nueva reserva, cambio de plan, etc.), siempre conviene refrescarlas al login.

Ejemplo 1 — Flujo de Signup (Registro de nuevo usuario)

Este es el momento más importante: el usuario se registra por primera vez. Querés capturar sus atributos iniciales para poder mostrarle una Guide de bienvenida personalizada.

import { track, identify, Identify } from "@amplitude/unified";
import amplitude from "@amplitude/unified";

async function onSignupSuccess(formData: SignupForm) {
  // 1. Identificar al usuario recién creado
  amplitude.setUserId(formData.userId);

  // 2. Registrar el evento de signup
  track("signup_completed", {
    metodo_registro: formData.metodo,       // "email" | "google" | "facebook"
    origen_campana: formData.utmSource,
    tipo_viajero_seleccionado: formData.tipoViajero,
  });

  // 3. Actualizar el perfil del usuario con identify
  const id = new Identify();
  id.set("tipo_viajero", formData.tipoViajero);      // "aventura" | "relax" | "cultural"
  id.set("destino_interes", formData.destinoInteres);
  id.set("tiene_cuenta", true);
  id.set("reservas_completadas", 0);
  id.setOnce("fecha_registro", new Date().toISOString());
  id.setOnce("primer_destino_interes", formData.destinoInteres);
  identify(id);
}

¿Qué Guide se puede activar aquí?

  • Trigger: On event tracked: signup_completed
  • Contenido personalizado: "Hola, viajero de {{property.tipo_viajero}}. Empecemos a planear tu próxima aventura."
  • Lógica condicional: Si tipo_viajero = aventura → mostrar destinos de trekking. Si tipo_viajero = relax → mostrar destinos de playa.

Ejemplo 2 — Flujo de Add to Cart (Agregar al carrito)

El usuario agrega un paquete de viaje al carrito. Es un momento de alta intención: podés usar una Guide para reducir el abandono o hacer upsell.

import { track, identify, Identify } from "@amplitude/unified";

async function onAddToCart(paquete: PaqueteViaje) {
  // 1. Registrar el evento con las propiedades del paquete
  track("add_to_cart", {
    paquete_id: paquete.id,
    destino: paquete.destino,              // "Torres del Paine"
    tipo_paquete: paquete.tipo,            // "aventura" | "relax" | "cultural"
    duracion_noches: paquete.noches,       // 5
    precio: paquete.precio,               // 280000
    moneda: "CLP",
    tiene_vuelo_incluido: paquete.incluyeVuelo,
  });

  // 2. Actualizar propiedades del usuario que cambian con esta acción
  const id = new Identify();
  id.set("ultimo_destino_carrito", paquete.destino);
  id.set("ultimo_precio_carrito", paquete.precio);
  id.set("tiene_carrito_activo", true);
  id.set("tipo_viajero", paquete.tipo);
  id.add("items_en_carrito", 1);
  identify(id);
}

¿Qué Guide se puede activar aquí?

  • Trigger: On event tracked: add_to_cart
  • Lógica condicional:
    • Si tiene_vuelo_incluido = false → mostrar upsell de vuelo
    • Si duracion_noches >= 7 → ofrecer seguro de viaje extendido
    • Si reservas_completadas = 0 → mostrar guía de "cómo funciona tu primera reserva"
  • Contenido: "Agregaste {{property.ultimo_destino_carrito}} a tu carrito. ¿Completamos tu reserva?"

Ejemplo 3 — Flujo de Purchase (Reserva completada)

El usuario confirma y paga la reserva. Es el evento más valioso: actualizás el perfil con el historial de compra y podés activar una encuesta de satisfacción o una Guide de próximos pasos.

import { track, identify, Identify } from "@amplitude/unified";

async function onPurchaseSuccess(reserva: Reserva) {
  // 1. Registrar el evento de compra
  track("purchase_completed", {
    reserva_id: reserva.id,
    destino: reserva.destino,
    tipo_paquete: reserva.tipo,
    duracion_noches: reserva.noches,
    monto_total: reserva.monto,
    moneda: "CLP",
    metodo_pago: reserva.metodoPago,       // "tarjeta" | "transferencia"
    fecha_viaje: reserva.fechaInicio,
  });

  // 2. Actualizar el perfil del usuario
  const id = new Identify();
  id.add("reservas_completadas", 1);
  id.set("tiene_reserva_activa", true);
  id.set("tiene_carrito_activo", false);
  id.set("ultimo_destino_reservado", reserva.destino);
  id.set("fecha_proximo_viaje", reserva.fechaInicio);
  id.set("monto_ultima_reserva", reserva.monto);
  id.append("destinos_reservados", reserva.destino);
  id.setOnce("primer_destino_reservado", reserva.destino);
  identify(id);
}

¿Qué experiencia se puede activar aquí?

  • Trigger: On event tracked: purchase_completed
  • Audience: reservas_completadas >= 1
  • Encuesta NPS con ramificación por score (0-6 → mejora · 7-8 → qué faltó · 9-10 → reseña en app store)
  • Guide de próximos pasos: "Tu viaje a {{property.ultimo_destino_reservado}} es el {{property.fecha_proximo_viaje}}. Descargá el itinerario."

4. Patrón completo al inicio de sesión

Además de los flujos puntuales, siempre conviene llamar a identify() al inicio de cada sesión para refrescar propiedades que pueden haber cambiado en el backend.

import { initAll, identify, Identify } from "@amplitude/unified";
import amplitude from "@amplitude/unified";

async function initAmplitude(usuario: Usuario | null) {
  // 1. Inicializar el SDK
  initAll("TU_API_KEY", {
    analytics: { defaultTracking: true },
    sessionReplay: { sampleRate: 0.5 },
    engagement: {},
  });

  // 2. Si hay sesión activa, identificar al usuario
  if (usuario) {
    amplitude.setUserId(usuario.id);

    // 3. Traer datos frescos del backend
    const perfil = await api.getPerfil(usuario.id);

    // 4. Actualizar propiedades con identify
    const id = new Identify();
    id.set("tipo_viajero", perfil.tipoViajero);
    id.set("reservas_completadas", perfil.reservasCompletadas);
    id.set("tiene_reserva_activa", perfil.tieneReservaActiva);
    id.set("fecha_proximo_viaje", perfil.fechaProximoViaje);
    id.set("plan", perfil.plan);           // "free" | "premium"
    identify(id);
  }
}

// Llamar al cargar la app
initAmplitude(sessionStorage.getUsuario());

6. Resumen: flujo completo integrado

Flujo completo integrado

Las 5 reglas para implementar correctamente

  1. initAll() va una sola vez en el entry point de la app, antes de cualquier track o identify.
  2. setUserId() antes de identify() — siempre identificá al usuario antes de actualizar sus propiedades.
  3. identify() al inicio de cada sesión con datos frescos del backend para que Guides & Surveys tenga propiedades actualizadas.
  4. track() + identify() juntos en cada acción importante — el evento registra qué hizo, el identify actualiza quién es.
  5. Los nombres de propiedades deben coincidir exactamente entre el identify() del código y la variable {{property.nombre}} en el editor de Guides & Surveys.
