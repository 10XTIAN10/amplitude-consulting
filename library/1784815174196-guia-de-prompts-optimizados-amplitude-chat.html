📊 Prompt #1

Analizar Charts del Dashboard

🎯 Objetivo

Obtener un análisis profundo de cada gráfico en un dashboard, identificando tendencias, anomalías y oportunidades de optimización.

👤 Rol

Analista de datos senior especializado en product analytics

⏱️ Cuándo usarlo

  • ✅ Revisiones semanales o mensuales de performance
  • ✅ Preparación de reportes para stakeholders
  • ✅ Cuando necesitas una visión holística del estado de tu producto

📝 Prompt:

Actúa como un analista de datos senior especializado en product analytics y descubrimiento de insights accionables. Tu objetivo es identificar patrones ocultos, anomalías significativas y oportunidades de crecimiento que otros podrían pasar por alto.

Analiza en profundidad cada chart de este dashboard durante los últimos 30 días:
[pega el link del dashboard]

Para la comparación con el período anterior:

Si los charts del dashboard NO tienen period-over-period configurado:
1. Consulta directamente los eventos del período anterior (30 días previos) usando amplitude_mcp_query_dataset
2. Calcula las métricas clave para ambos períodos
3. Genera la comparación manualmente para identificar cambios

Si los charts SÍ tienen period-over-period configurado:
1. Usa los datos de comparación ya disponibles en los charts
2. Analiza las variaciones period-over-period directamente

Para cada gráfico, identifica y presenta en formato de tabla:
- Tendencias principales y patrones de comportamiento por segmento de usuarios
- Anomalías o cambios significativos (especifica fechas y magnitud del cambio)
- Diferencias entre segmentos clave: usuarios móviles vs web, nuevos vs recurrentes, por plan de suscripción
- Oportunidades de optimización basadas en los datos
- Correlaciones entre métricas que puedan revelar insights accionables
- Comparación vs. período anterior: cambios >10% con hipótesis de causas

Prioriza los hallazgos en una lista numerada por impacto potencial en conversión y retención.
Incluye links a los charts específicos donde encontraste cada insight.

💡 Tip: Comparación de períodos Este prompt incluye comparación automática con el período anterior. Si los charts no tienen period-over-period configurado, Amplitude consultará directamente los eventos del período anterior para generar la comparación.

Puedes personalizar el período:

  • "últimos 7 días" (compara con los 7 días previos)
  • "abril 2026" (compara con marzo 2026)
  • "Q1 2026" (compara con Q4 2025)
✏️ Prompt #2

Editar Dashboard (Agregar Descripciones)

🎯 Objetivo

Que Amplitude agregue automáticamente descripciones y contexto a cada chart del dashboard para hacerlo más comprensible, sin modificar los nombres existentes.

👤 Rol

Especialista en visualización de datos y comunicación ejecutiva

⏱️ Cuándo usarlo

  • ✅ Dashboards para equipos de negocio o marketing
  • ✅ Presentaciones para liderazgo ejecutivo
  • ✅ Cuando necesitas que un dashboard sea self-service

📝 Prompt:

Actúa como un especialista en visualización de datos y comunicación de insights para stakeholders ejecutivos. Tu objetivo es transformar dashboards técnicos en narrativas claras que impulsen decisiones de negocio.

Edita este dashboard agregando descripciones y contexto a cada chart:
[pega el link del dashboard]

Para cada chart del dashboard:
1. MANTÉN el nombre/título actual del chart sin modificarlo
2. AGREGA una descripción de 2-3 líneas que explique:
   - Qué mide exactamente este chart
   - Por qué es importante para el negocio
   - Cómo interpretarlo (qué es bueno/malo, rangos esperados)
   - Contexto adicional relevante (benchmarks, metas, comparaciones)

Para el dashboard completo:
- AGREGA un título general descriptivo si no tiene uno
- AGREGA una descripción general del dashboard explicando su propósito y cómo usarlo
- ORGANIZA los charts en secciones temáticas si aplica (ej: Adquisición, Activación, Retención)
- AGREGA notas o anotaciones donde sea necesario para facilitar la interpretación

Ejecuta estos cambios directamente en el dashboard.
VERIFICACION: Confirma que las descripciones se agregaron correctamente a cada chart.

⚠️ Importante: Este prompt NO modifica los nombres de los charts existentes, solo agrega descripciones y contexto.

🔍 Prompt #3

Investigar Abandono en Funnels

🎯 Objetivo

Investigar a fondo las causas de abandono en un funnel de conversión y generar hipótesis accionables.

👤 Rol

Experto en optimización de conversión y análisis de comportamiento

⏱️ Cuándo usarlo

  • ✅ Cuando observas caídas en conversión
  • ✅ Necesitas justificar inversión en UX/producto
  • ✅ Quieres priorizar mejoras en el flujo de usuario

📝 Prompt:

Actúa como un experto en optimización de conversión y análisis de comportamiento de usuarios. Tu objetivo es diagnosticar las causas raíz del abandono en funnels aplicando metodologías rigurosas de análisis cuantitativo y cualitativo.

Investiga a fondo por qué los usuarios abandonan este funnel en los últimos 30 días:
[pega el link del chart de funnel]

Analiza y presenta los resultados en secciones claras:

1. Análisis de caída por paso:
- Identifica el paso con mayor drop-off (% y número absoluto de usuarios)
- Tiempo promedio entre pasos para usuarios que convierten vs. abandonan

2. Segmentación de usuarios:
Compara tasas de conversión entre:
- Usuarios móviles (iOS/Android) vs web (desktop/mobile web)
- Nuevos usuarios vs recurrentes
- Por fuente de adquisición (orgánico, paid, referral, etc.)
- Por geografía (top 5 países)
- Por plan o tipo de cuenta (si aplica)

3. Análisis de comportamiento:
- Eventos o acciones previas al funnel que correlacionan con conversión exitosa
- Eventos que realizan quienes abandonan vs. quienes convierten
- Patrones temporales: días de la semana y horas del día con peor conversión

4. Hipótesis de causas raíz:
Lista numerada de 3-5 hipótesis concretas priorizadas por probabilidad e impacto.

Compara con el período anterior (30 días previos) para identificar si el problema es nuevo o recurrente.
Incluye el link al funnel en tu análisis.
🧪 Prompt #4

Diseñar Experimentos A/B

🎯 Objetivo

Diseñar experimentos A/B concretos y priorizados para mejorar la conversión en un funnel.

👤 Rol

Growth Product Manager con expertise en experimentación

⏱️ Cuándo usarlo

  • ✅ Después de identificar problemas de conversión (Prompt #3)
  • ✅ Para pasar del diagnóstico a la acción
  • ✅ Cuando necesitas experimentos bien diseñados y priorizados

📝 Prompt:

Actúa como un growth product manager con expertise en experimentación y metodología científica. 
Tu objetivo es diseñar experimentos A/B rigurosos, priorizados y accionables que maximicen el aprendizaje y el impacto en conversión.

Basándote en el análisis de este funnel durante los últimos 30 días, diseña 5 experimentos concretos para mejorar la conversión:
[pega el link del chart de funnel]

Para cada experimento, estructura la información así:

Experimento #[N]: [Nombre descriptivo]
- Hipótesis: [Declaración específica y medible]
- Segmento objetivo: [Quiénes exactamente: ej. "usuarios móviles iOS que abandonan en el paso 2"]
- Tamaño del segmento: [Usuarios/semana disponibles para el test]
- Intervención propuesta: [Cambio específico a implementar - ej. "reducir campos del formulario de 8 a 4"]
- Métrica primaria: [Ej. "Tasa de conversión del paso 2 al 3"]
- Métricas secundarias: [Ej. "Tiempo en paso, tasa de error, conversión end-to-end"]
- Duración estimada: [Semanas necesarias para significancia estadística]
- Esfuerzo de implementación: [Bajo/Medio/Alto]
- Impacto esperado: [% de mejora estimada]
- Riesgos a monitorear: [Ej. "calidad de leads, tasa de rebote posterior"]

Presenta los experimentos en una tabla comparativa final con columnas:
Experimento | Esfuerzo | Impacto Esperado | Prioridad (1-5)

Prioriza considerando la matriz esfuerzo vs. impacto.
Incluye el link al funnel y sugiere cómo crear cohorts en Amplitude para cada segmento objetivo.
📈 Prompt #5 — BONUS

Comparar Períodos

🎯 Objetivo

Comparar el rendimiento entre dos períodos para identificar cambios significativos y sus posibles causas, incluso cuando los charts no tienen period-over-period configurado.

👤 Rol

Analista de Business Intelligence enfocado en tendencias temporales

⏱️ Cuándo usarlo

  • ✅ Revisiones trimestrales (QBR)
  • ✅ Análisis de estacionalidad
  • ✅ Evaluar impacto de lanzamientos de producto
  • ✅ Comparar rendimiento mes a mes o año a año

📝 Prompt:

Actúa como un analista de business intelligence enfocado en análisis de tendencias temporales y estacionalidad. Tu objetivo es identificar cambios significativos entre períodos y explicar sus causas con hipótesis fundamentadas.

Compara el rendimiento de este dashboard entre [Período 1: ej. Q1 2026 (enero-marzo)] vs [Período 2: ej. Q4 2025 (octubre-diciembre)]:
[link del dashboard]

Si los charts del dashboard NO tienen period-over-period configurado:
1. Consulta directamente los eventos del período anterior usando amplitude_mcp_query_dataset
2. Calcula las métricas clave para ambos períodos
3. Genera la comparación manualmente

Si los charts SÍ tienen period-over-period configurado:
1. Usa los datos de comparación ya disponibles en los charts
2. Analiza las variaciones y tendencias

Para el análisis:
- Identifica cambios significativos (>10%) en métricas clave
- Explica posibles causas estacionales, de producto o de mercado
- Segmenta por dimensiones relevantes (país, canal, plataforma, etc.)
- Presenta los hallazgos en formato de tabla con columnas: Métrica | [Período 1] | [Período 2] | Cambio % | Insight

Incluye:
- Tabla comparativa de métricas principales
- Gráficos o visualizaciones si es posible
- Hipótesis sobre las causas de los cambios más significativos
- Recomendaciones de acciones a tomar basadas en los hallazgos

⚠️ Limitaciones comunes y soluciones

🚧 Limitación✅ Solución
Charts sin PoP configuradoAmplitude consultará directamente los eventos del período anterior usando amplitude_mcp_query_dataset
Rangos de fechas fijosEspecifica explícitamente las fechas del período anterior en el prompt
Métricas calculadas complejasSolicita que se replique el cálculo para ambos períodos
Segmentaciones no disponiblesPide que se consulten los eventos raw con las dimensiones necesarias

📊 Mejores prácticas

  • ✅ Especifica fechas exactas para ambos períodos (no solo "Q1 vs Q2")
  • ✅ Define el umbral de cambio significativo (ej: >10%, >15%)
  • ✅ Lista las métricas prioritarias que quieres comparar
  • ✅ Menciona segmentaciones clave (país, canal, plataforma, cohorte)
  • ✅ Pide hipótesis fundamentadas sobre las causas de los cambios
📓 Prompt #6

Documentar Resultados en Notebook

🎯 Objetivo

Documentar automáticamente los resultados de un análisis en un notebook de Amplitude para compartir con el equipo y mantener un registro histórico.

👤 Rol

Analista de datos que documenta hallazgos de forma estructurada y profesional

⏱️ Cuándo usarlo

  • ✅ Compartir insights con equipos multifuncionales
  • ✅ Crear registro histórico de análisis
  • ✅ Documentar decisiones basadas en datos
  • ✅ Facilitar onboarding de nuevos miembros

📝 Prompt Base:

Actúa como un analista de datos que documenta sus hallazgos de forma estructurada y profesional para compartir con equipos multifuncionales.

[Aquí va el prompt de análisis que quieras ejecutar - puede ser cualquiera de los prompts #1 a #5]

Con el resultado del análisis genera un notebook en Amplitude que incluya:
- Título descriptivo del análisis realizado
- Fecha y período analizado
- Resumen ejecutivo (3-5 puntos clave)
- Hallazgos detallados con visualizaciones y links a charts
- Recomendaciones accionables priorizadas
- Próximos pasos sugeridos

NOTEBOOK - INSTRUCCIÓN CRÍTICA DE ORDEN: Después de crear el notebook, SIEMPRE llama a get_notebook para verificar el orden real de las filas. Si alguna fila está fuera de lugar, usa edit_notebook con set_rows para reordenar todas las filas en el orden correcto antes de compartir el link. No compartas el link del notebook sin haber verificado y corregido el orden.
Comparte el link del notebook en este hilo.
